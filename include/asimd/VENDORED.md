# asimd, vendored

Copy of `src/asimd` from the repository https://github.com/hleclerc/asimd (commit `dd45dad`, "load_partial /
store_partial: the lanes of a set, not one byte outside"), as it is also brought back into
`2d_des_familles/ext/asimd` for the bench.

Here because the kernels generated by `loom` are compiled with `-I sdot/include` and nothing else
(see `loom/compilation/__init__.py::cpp_include_root`), and because the installed wheel ships
this tree as is. To update: copy `src/asimd` over from the repository and note the commit here.

Local deviation (2026-09-21, to be reported upstream): `HaD` removed from the three functions that take or return a
`__m256` / `__m256d` (`ops/X86.h::avx_lane_ext_ps/pd`, `impl/SimdVecImpl_AVX.h`) -- nvcc refuses an
x86 vector type in a `__host__ __device__` signature, even on a template never instantiated
on the device side. These functions are x86 only, `inline` is enough.
